# 量潮创始人档案

收创始人领域蒸馏出的稳定档案。

`think/` 按**事情**重组：一个事情一组，回答「我在思考或推动哪些事情」「某件事思考到什么程度了」；情境（触发点）与事件作为条目挂在事情下，情绪 / 方法 / 价值随条目走，事情卡记蒸馏程度（想法 → 情境 → 方法 → 价值），入口见 [think/index.md](./think/index.md)。来源：原 `think/`（按情境）与 `work/`（按事件）合并重组，条目原文基线 `git show fe651c1:think/…`、`git show fe651c1:work/…`；更早五轴基线 `git show f4013d1:default/…`、`git show 86e8532:work/…`。

`work/` 收**推动中事项的对象档案**（事项台账）：一个事项一档（现状 / 依据 / 下一步），回答「这条工作线做了什么决定、做到哪」；与 `think/` 分工——认知应对与价值归 `think/`，事实与决定归 `work/`，互链不重复；蒸馏通道 `data/context` 各分区日志 → `work/`（以各档标注为准），入口见 [work/index.md](./work/index.md)。

`execute/` 收**任务清单**：只列可执行的任务与状态，回答「现在手上要做哪些事」；任务背后的决定与依据仍留在 `work/`，入口见 [execute/index.md](./execute/index.md)。

`write/` 收创作认知地图与创作档案：卡在什么（困境）、怎么写（方法）、为什么写（动机），入口见 [write/index.md](./write/index.md)。

`product/` 收**需求档案**：`requirement/` 收与 AI 协作时反复出现的差，按主题一档（观察 / 类型 / 规则三档，原始条目以 `clr_` id 指回账本不复制原文）；顶层放具体产品的需求文档。入口见 [product/index.md](./product/index.md)。
