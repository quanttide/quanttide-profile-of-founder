# work 档案框架（按事件重组）

> 从 `work/` 的五类档案按**事件**重组——一个事件一组，情绪 / 方法 / 价值挂在它所处的事件下，挂不上事件的进 `loose-entries`（原文件已清理，基线 `git show 86e8532:work/…`）：一组三格式——`.md` 条目原文、`.lino` 链接记法（一行一条边）、`.ttl` 图谱节点与态射；本目录 `index.*` 概括框架。

## 相关事件的分工

- 「目标完成又冒出新需求」与「想法不断冒出」：前者是外部需求、带落差；后者是内部想法、只做分流。
- 「供需双方都卡住」与「想法说不出来」：前者卡在方向，应对是先放下；后者卡在表达，应对是先说出来。
- 「文件成了垃圾堆」与「维护场景要同时保质量与产出」：前者是失序后的恢复，应对是定关键下一步；后者是常态下的维持，应对是分权制衡。

## 未接边与待填充

- 只带方法、没有事件或情绪的组（想法不断冒出、快速验证、维护场景）暂不接边，先把情境立住。
- 跨组的边只记在 `index.lino` 与 `index.ttl`，组内文件不重复。
- 方法容器（`思维框架` / `应对策略` 两个小节标题）随重组打散，不再作为条目。
